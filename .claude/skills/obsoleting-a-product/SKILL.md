# Obsoleting a BNC product

## When to use this skill

The user asks to discontinue/retire a product on berkeleynucleonics.com, add it to
the obsolescence cross-reference, point customers to its replacement, and/or make
sure it stops showing up in search as if it were still for sale. Trigger phrases:
"obsolete this product", "add X to the obsolete products page", "X is discontinued,
Y replaces it", "hide the datasheet from search for a retired product".

## The steps, in order

### 1. Add the row to `obsolete-products.html`

Find the right category table (`<h2>` matches the product's line: Pulse & Delay
Generators, Arbitrary Waveform Generators, RF & Microwave Signal Generators,
Isotope ID & Radiation Detection, High Voltage & Pulsed Power, Multimeters/
Spectrum Analyzers/Other). Add a row matching the existing format exactly:

```html
<tr><td>{Obsolete Product}</td><td><a href="docs/{replacement-datasheet}.html">{Replacement Model}</a></td><td>{short note}</td></tr>
```

If there is no direct replacement, link to `contact.html` with text "Contact" and
note "Team will advise on a successor", or link the product-line home page with
text "No direct replacement" - both patterns already exist in the table, follow
whichever fits.

### 2. Make the new model numbers searchable

The search index (`_shared/bnc-search-index.js`) is generated by
`scripts/reindex-site-search.py` from a **pre-harvested text cache**,
`scripts/page-harvest.json`. That cache is not regenerated by anything in this
repo - it is a static snapshot, so it goes stale the moment you edit a page's
content. Skipping the refresh below is the single most common way this task
silently fails (the row looks right on the page, but the model number still
doesn't turn up in search).

```
python scripts/refresh-harvest-entry.py obsolete-products.html
python scripts/reindex-site-search.py
```

(Use `python`, not `python3`, in this environment - `python3` resolves to a
Microsoft Store stub that fails.)

Verify before moving on - parse the generated file rather than eyeballing it:

```python
import re, json
src = open('_shared/bnc-search-index.js', encoding='utf-8').read()
idx = json.loads(re.search(r'window\.SITE_INDEX=(\[.*?\]);\nwindow\.SSDESC', src, re.S).group(1))
for e in idx:
    if e['u'] in ('obsolete-products.html', 'docs/bnc-model-XXXb-datasheet.html'):
        print(e['u'], '588' in e['k'], '588b' in e['k'])  # adapt the tokens
```

### 3. Hide the obsolete product's own datasheet/manual from search (do not delete it)

The goal: a customer searching the old model number should see
`obsolete-products.html` and the *replacement's* page, not a datasheet for a
product BNC no longer sells reading as if it were current.

- First check whether the obsolete product even has its own page in `docs/` -
  most of the older rows on this page never got a modern datasheet/manual and
  there is nothing to hide.
- **Before excluding anything, confirm the page is unambiguously the
  discontinued unit.** A model number can be reused: "Model 676" is both an
  obsolete row on this page *and* a currently-shipping AWG datasheet
  (`docs/bnc-awg-676-datasheet.html`). Check the page's own `<h1>` and confirm
  it isn't a live, current product before adding it to the list below. When in
  doubt, leave it indexed and flag the ambiguity to the user rather than
  guessing.
- Add each confirmed URL to `SUPERSEDED_URLS` near the top of
  `scripts/reindex-site-search.py`, then re-run the reindex script again. The
  page itself is untouched (confirm with `git diff -- <path>` showing nothing)
  - it just stops appearing in `window.SITE_INDEX`.

### 4. Live-verify before shipping

Open a **fresh** browser tab (not a reloaded existing one - the search engine
runs inside a closure per page load, so an already-open tab can keep running
old logic even after a hard reload) and actually type the model number into
the search box. Confirm: the old page doesn't appear, the replacement and
`obsolete-products.html` do.

### 5. Ship it: branch, PR, and the generated-file conflict

Per this repo's standing rule, never push straight to `main` - branch, commit,
push the branch, open a PR for manual merge.

`_shared/bnc-search-index.js` (and `scripts/page-harvest.json` if you touched
it) are essentially single-line generated JSON blobs. If `main` has moved
since you branched, **a merge will conflict on these files almost every
time** - git cannot line-merge two independent regenerations of a one-line
file. Do not hand-edit the conflict. Instead:

```
git fetch origin main
git rebase origin/main
# on conflict in the generated files only:
git checkout --ours -- _shared/bnc-search-index.js scripts/page-harvest.json
git add _shared/bnc-search-index.js scripts/page-harvest.json
python scripts/refresh-harvest-entry.py <any page you edited>   # if applicable
python scripts/reindex-site-search.py                            # regenerate fresh
git add _shared/bnc-search-index.js scripts/page-harvest.json
git rebase --continue
git push --force-with-lease origin <branch>
```

If the branch's PR was already merged by the time you have follow-up commits,
don't try to reuse it - `git log origin/main..<branch>` to see what's actually
new, and open a fresh PR for just that.

## Background (already fixed permanently, no action needed)

Fixed once in `scripts/reindex-site-search.py` and the shared search engine,
these no longer need to be worked around:

- Model-number extraction used to cap at the first 1200 characters of a
  page's body text, silently dropping every model past the opening of long
  pages like this one. It now scans full text.
- The debug-dump path in the reindexer used to be hardcoded to another
  machine's job directory and crashed on every run here. It now uses the OS
  temp dir.
- The client-side matcher (`wbHas` in `index.html`, propagated to every page)
  used to require an exact whole-word match, so a shorter query like
  "ICX-060" would not match a longer indexed token like "ICX-060U-P". It now
  matches on word-start (prefix), so a partial model number still finds the
  fuller one.
